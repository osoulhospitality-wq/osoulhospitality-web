# تشغيل التحسين المستمر

تشغّل GitHub Actions فحوص JavaScript وفحوص استعادة الذاكرة عند طلب الدمج، وعند التشغيل اليدوي، وكل اثنين الساعة 04:20 بالتوقيت العالمي. تحفظ خطوة التحقق سجل التثبيت ونتائج المجموعتين ورموز الخروج في حزمة draqon-synthetic-results لمدة 14 يومًا. يؤدي فشل أي مجموعة إلى إخفاق التشغيل. تشغَّل كل مجموعة حتى لو فشلت المجموعة السابقة.

عند إخفاق الفحص المجدول أو اليدوي على الفرع الافتراضي، يحسب النظام توقيعًا ثابتًا لمجموعة الحالات الفاشلة ويُعِد طلب دمج مسوّدة يحتوي مستندًا فقط. يفحص طلبات الدمج السابقة والحالية بالفرع والتوقيع. إذا انقطع الاتصال بعد رفع الفرع وقبل إنشاء الطلب، يتحقق من أن فرق الفرع يقتصر على مستند مطابق للأدلة قبل الاستئناف. تُوقف المطابقة الفاشلة العملية للمراجعة. تحمل طلبات الدمج الواردة صلاحيات قراءة فقط.

يربط المهندس المقترح بالتشغيل الفاشل، ويعيد إنتاج الحالة في نسخة معزولة، ويضيف إصلاحًا واختبار ارتداد ومقياس مقارنة وخطة تراجع. يراجع مسؤول مستقل النتيجة، ويعتمد صاحب الصلاحية النقل التدريجي. بعده تقارن المراقبة العيوب وتكلفة المهمة وزمنها بالإصدار السابق. تراجع صلاحيات النشر والحدود المالية والقرارات الجوهرية بصورة منفصلة.

للتشغيل المحلي استخدم `npm ci` ثم `npm run test:enterprise`. للحصول على سجل مفصّل لفحوص المعرفة عيّن `DRAQON_MEMORY_TEST_REPORT` إلى مسار ملف أدلة خارج المستودع، ثم شغّل `python3 automation/enterprise/memory/verify_memory.py`. لإتاحة المقترحات الآلية على GitHub، يجب اعتماد الملف في الفرع الافتراضي والتحقق من إعداد السماح لـGitHub Actions بإنشاء طلبات دمج. جرى اختبار الاستئناف محليًا بمستودع Git مؤقت واستجابات GitHub اصطناعية. يلزم تشغيل شاهد على مستودع تجريبي للتحقق من سياسات المؤسسة والجدولة واحتفاظ الأدلة.
