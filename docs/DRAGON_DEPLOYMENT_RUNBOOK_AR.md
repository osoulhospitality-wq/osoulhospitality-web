# دليل نشر Dragon Intake Production

## النتيجة المستهدفة

عند إنشاء أو إعادة فتح أو تعديل GitHub Issue مفتوح يحمل التصنيف `dragon-task`، يقوم التدفق تلقائيًا بما يلي:

1. يتحقق من صلاحية الحدث ويمنع التكرار.
2. يضيف `dragon-processing`.
3. يسجل تعليق استلام يتضمن رقم التنفيذ.
4. يرسل المهمة إلى Dragon Executive Agent.
5. ينشر المخرج التنفيذي داخل الـIssue.
6. يحول الحالة إلى `dragon-completed`.
7. إذا فشل الوكيل، يسجل سبب الفشل ويطبق `dragon-failed` دون ادعاء الإنجاز.

## الملفات

- `dragon-intake-production.workflow.json`: ملف n8n الجاهز للاستيراد.
- `DRAGON_DEPLOYMENT_RUNBOOK_AR.md`: دليل النشر والقبول التشغيلي.

## ضوابط الأمان

- لا يحتوي الملف على Token أو API Key.
- لا تُدخل الأسرار داخل أي عقدة نصية؛ استخدم Credentials في n8n فقط.
- اعتماد GitHub المطلوب هو الاتصال الناجح الحالي باسم `GitHub account`.
- يلزم اعتماد OpenAI API داخل n8n باسم `OpenAI account` أو إعادة ربط عقدة النموذج بالاسم الموجود فعليًا.
- تم تجهيز تصنيفات الحالة في المستودع: `dragon-processing` و`dragon-completed` و`dragon-failed`.
- لا تجعل Workflow الاختبار القديم والجديد نشطين في الوقت نفسه؛ كلاهما قد ينشئ Webhook للحدث نفسه ويكرر التنفيذ.

## النشر داخل n8n

1. افتح Workflows ثم اختر Import from File.
2. استورد `dragon-intake-production.workflow.json`.
3. افتح كل عقد GitHub وحدد اعتماد `GitHub account` الناجح.
4. افتح `OpenAI Chat Model` وحدد اعتماد OpenAI الصحيح.
5. تأكد أن النموذج `gpt-5.6-sol` متاح في اعتماد OpenAI. هذا هو النموذج الحالي الذي أعاده محلّل النماذج الرسمي في 26 يوليو 2026. لا تستبدله باسم منتج داخلي أو اسم غير موثق.
6. احفظ التدفق.
7. عطّل Workflow الاختبار القديم قبل تفعيل الجديد.
8. نفذ اختبار القبول أدناه.
9. بعد نجاح الاختبار اضغط Publish/Activate.

## معايير النجاح

- يظهر تعليق `Dragon accepted this task`.
- يصبح التصنيف `dragon-processing`.
- يظهر تعليق `Dragon delivery` بمحتوى غير فارغ.
- يصبح التصنيف النهائي `dragon-completed`.
- لا يبقى `dragon-processing`.
- يظهر Execution ناجح واحد فقط في n8n.
- إعادة تعديل Issue بعد اكتماله لا تنشئ تنفيذًا جديدًا.

## معايير الفشل الآمن

إذا تعطل نموذج الذكاء الاصطناعي:

- يظهر تعليق `Dragon execution failed safely`.
- يصبح التصنيف `dragon-failed`.
- لا يظهر `dragon-completed`.
- يحتوي سجل n8n على رسالة خطأ قابلة للتتبع.

## ملاحظة تشغيلية مهمة

هذا التدفق ينفذ الاستلام والتحليل وإنتاج المخرج والتسجيل والحالات تلقائيًا. تنفيذ تغييرات فعلية داخل الملفات أو إنشاء Pull Requests يحتاج لاحقًا إلى توصيل أدوات GitHub المصرح بها بالوكيل وفق سياسة فروع محمية؛ لا ينبغي منح الوكيل صلاحية الكتابة المباشرة إلى `main`.
