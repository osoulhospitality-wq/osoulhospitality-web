# Facility rate and sales review

The private daily price report covers one check-in. The weekly report covers seven individual check-ins. Use Riyadh dates and keep the observed timestamp with its UTC offset. The public partner exercise uses simulated observations and has no connection to this pipeline.

## Reviewer workflow

1. Scope the review to the mapped organization, client and facility. Read aggregate on-the-books sales from an authorized source, including the unit category, stay date, sellable capacity, booked nights and the observation time. Separate on-the-books quantities from realized revenue. When the PMS or source is unavailable, keep missing measures null.
2. Identify the subject and peers on a map. Record the property identity, district and service level. Collect bookable offers for the same stay night, unit category, occupancy, cancellation deadlines, meals, public customer eligibility and mandatory charges. Check the currency and refundable deposits separately. Do not substitute an expired quote, pre-tax starting price or seven-night average for a one-night offer. An unavailable listing can be evidence about one channel only.
3. Check dated flight supply, confirmed events and newly announced postponements. Record the precise location and the affected stay dates. Airport schedules show flights; passenger loads and local hotel demand require their own evidence. When ticket volumes or cancellation data are missing, report the event as a monitoring signal. Record sources for accepted and rejected signals.
4. Run the dependency-free calculator on a reviewed collection of one-night observations. Keep inputs and output private. For a numeric suggestion the pilot requires the facility's valid quote, three distinct comparable properties and a current inventory snapshot with remaining units. Each property has one vote across channels. Qualified nightly ranges use observed market quartiles, adjusted only when matched booking pace is available. The result is a candidate price band for a revenue manager to test. It does not optimize net profit or account for a private rate floor by default.
5. Forecast final sold rooms only with at least six unique completed comparable dates, same weekday, lead time, unit and inventory. The calculation adds historical median remaining net pickup (including cancellations) to current bookings and bounds the result by sellable inventory. Record sample size, source, uncertainty and last week's forecast error once actuals exist. Inspect approved seasonal and inventory changes before using the result.
6. Store the annotated snapshot through the private procedure defined in the facility revenue migrations. Supply the current revision, keep the procedure receipt and verify through the protected history. Inspect the latest SQL contract for required fields. Only review prices in this workflow; there is no channel write. Compare like-for-like source periods in the owner dashboard.

## Calculator

Run `node automation/revenue/rate-review.mjs < private-observations.json`. The input is an array with a `target`, an optional `ownQuote`, `peers`, optional `sales` and optional `history` for each night. Field names and representative synthetic inputs are exercised in `automation/tests/nightly-rate-review.test.mjs`. Use a stable property key across channels and a normalized unit category and district. Meal and cancellation fields describe the complete terms. Supply only public generally available rates. A source link points to the observed offer rather than a city landing page. The output's peer median is descriptive at any sample size; always show the number of distinct properties with it. Missing data never implies a zero price, occupancy or sales volume.

The two internal report schedules are maintained separately from the public site build. A successfully stored report, its sources and its stay dates provide the operating record.
