# Dragon Business Lifecycle — نواة تنفيذ محلية تجريبية

**الحالة: مطبّق ومختبر محليًا ببيانات مصطنعة فقط. غير منشور، وغير مربوط بالقنوات الحية.**

هذا المكون يختبر انتقال المسؤولية والبيانات عبر دورة أعمال واحدة بدل الاكتفاء بمخطط نظري. لا يمثل منظومة أصول الإنتاجية، ولا يشغّل نموذج ذكاء اصطناعي أو يرسل بريدًا أو يتصل بشبكة. لا يحتاج أي حزمة Python خارجية.

## ما ينفذه فعليًا

طلب → تأهيل → فرصة ومتابعة → عرض مع نطاق واستثناءات وسعر وتكلفة → اعتماد عرض أو رفضه → توثيق تفويض عقد → تكليف عمل لموظف → تسليم دليل → قبول جودة بدور مستقل → فاتورة تجريبية → تحصيل جزئي أو كامل → تجهيز مراجعة تجديد → تقرير حالات واستثناءات.

- كل معاملة مرتبطة بمؤسسة ومعرف حالة؛ تمنع العضوية الوصول إلى مؤسسة أخرى.
- عضوية المستخدم ودوره مقروءان من جدول مستقل، ولا يؤخذ الدور من محتوى الحدث.
- منع تكرار الحدث بمفتاح `(tenant,event_id)` وبصمة تشمل الفاعل والفعل والحالة والمحتوى. تكرار المفتاح بمحتوى مختلف يرفض.
- حالة العمل وأثر التدقيق وطابور الإشعارات المحاكى تحفظ في معاملة SQLite واحدة.
- التقرير المالي مقصور على المالك والمالية. `work_queue` يعرض للعمليات أعمال الموظف المسندة إليه فقط، دون السعر أو التكلفة.
- رفض البيانات الناقصة، وعدم وجود مسؤول، والعرض المنتهي، والانتقال دون متطلب سابق، واعتماد الموظف لعمله أو المبيعات لسعرها.
- مبالغ بوحدات العملة الصغرى الصحيحة فقط، وبعملة SAR؛ رفض السالب والكسور والزيادة على المستحق. مرجع التحويل فريد داخل المؤسسة حتى بين حالتين مختلفتين.
- حفظ سجل تدقيق مع قيود SQLite ضد التعديل والحذف العاديين. **مالك قاعدة البيانات يستطيع تغيير المخطط؛ هذا ليس سجلًا غير قابل للعبث أمام مسؤول قاعدة بيانات.**
- إعادة محاولة محاكاة بعد 60 ثم 120 ثانية، ثم `dead_letter` عند المحاولة الثالثة. النجاح اسمه `simulated_delivered` وليس إرسالًا خارجيًا مثبتًا.
- كشف تأخر المورد والتحصيل عند طلب التقرير. **لا توجد جدولة نشطة أو إرسال تنبيه تلقائي.**

## التشغيل

من جذر المستودع:

```bash
python3 automation/business-lifecycle/dragon_lifecycle.py demo
python3 automation/business-lifecycle/test_lifecycle.py --report /tmp/dragon-lifecycle-tests.json
```

لحفظ تجربة مستقلة قابلة لإعادة الفتح، استخدم مسارًا تجريبيًا جديدًا:

```bash
python3 automation/business-lifecycle/dragon_lifecycle.py demo --db /tmp/dragon-synthetic.sqlite
python3 automation/business-lifecycle/dragon_lifecycle.py report --db /tmp/dragon-synthetic.sqlite --as-of 2026-11-06
```

إعادة `demo` على الملف نفسه لا تكرر الأحداث. لا تستخدم ملف بيانات حقيقية. الـ CLI مثبت على تاريخ اختبار 25 أكتوبر 2026 لتظل التجربة قابلة للإعادة؛ المحرك الافتراضي يأخذ `date.today` من العملية الموثوقة. التاريخ لا يؤخذ من الحدث لتجاوز صلاحية العرض.

## واجهة الدمج

```python
from dragon_lifecycle import Engine
engine = Engine('/tmp/dragon-synthetic.sqlite')
engine.seed_synthetic_members('SYNTHETIC-A')  # تجهيز fixture محلي فقط
result = engine.apply(tenant, actor, event_id, action, case_id, payload)
report = engine.report(tenant, actor, as_of='2026-11-06')
queue = engine.work_queue(tenant, actor)
```

`seed_synthetic_members` أداة تجهيز للاختبار فقط. لا تعرضها عبر HTTP. `actor` و`tenant` مدخلان موثوقان داخل العملية في هذه النسخة؛ لم تُبنَ طبقة تسجيل دخول أو تحقق JWT. لا يجوز تحويل الدالة مباشرة إلى API عام، لأن العميل قد ينتحل معرف الفاعل إن لم تربطه المصادقة به.

## حالات الاختبار

المسار الكامل، إعادة الحدث، تضارب المفتاح، غياب البيانات والمسؤول، منع البيانات غير المصطنعة، فشل المتطلبات السابقة، فصل الاعتماد، رفض العرض، انتهاء السعر، تأخر المورد، التحصيل المتأخر والجزئي، تكرار مرجع الدفع داخل الحالة وبين حالتين، قيم مبالغ غير صالحة، المؤسسة الخاطئة، عزل مفتاح التكرار، فشل الموصل والانتظار والاستنفاد والتعافي، صلاحيات العامل، فصل الجودة، حماية سجل التدقيق، إعادة تشغيل قاعدة البيانات، ومنع كشف تكلفة العقود للموظف.

تقرأ نتيجة التشغيل من ملف JSON المولد. الأعداد ليست دليل قبول لخدمات خارجية.

## ما يحتاج تنفيذًا قبل الإنتاج

1. مصادقة خادم وربط هوية المستخدم وعضويته؛ منع fixture provisioning؛ فصل بيئة الاختبار.
2. دمج قاعدة التشغيل المعتمدة مع migrations وRLS واختبارات دخول حقيقية، ونسخ احتياطي واستعادة.
3. سجل موردين وملفات خاصة، والتحقق من أن دليل القبول والتوقيع حقيقي ومصرح، لا مجرد نص مرجعي كما في هذه التجربة.
4. عقود متعددة البنود والزيارات والتغييرات، سير إعادة العمل بعد رفض الجودة، وإصدارات العروض وتجديداتها؛ النسخة الحالية تختبر دورة مبسطة واحدة ولا تديرها كلها.
5. فاتورة نظامية وضريبة وسياسة توقيت الفوترة وتحقق محاسبي؛ الفاتورة هنا سجل اختبار وليست مستندًا ضريبيًا أو إثبات دخل.
6. موصلات CRM والبريد والملفات والمعرفة مع تفويض كل إرسال، وسياسة تعويض/تسوية عند غموض نجاح قناة خارجية. الطابور الحالي يحاكي الإرسال داخل قاعدة محلية، فلا يثبت ضمان الإرسال مرة واحدة في الشبكة.
7. جدولة فعلية ومراقبة وأخطاء منقحة ومسؤول احتياطي. لا تدع المتابعة مستمرة قبل تفعيل الجدولة واختبارها.
