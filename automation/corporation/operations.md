# مجلس دراقون لإدارة المرافق

يستعمل مكتب الإدارة التنفيذية سجل الأدوار المؤسسي لتوجيه ثلاثين اختصاصًا. يرفق بكل تكليف مسؤول إعداد ومراجع مختلف وبيانات الإثبات المطلوبة ومقياس قبول. يولد الموجّه إيصالًا محليًا يتضمن المؤسسة والمنشأة وتاريخ الرصد والمراجع وحالة التكليف وبصمته.

تعمل الأدوات التالية على Node.js 24 في جهاز تشغيل مخوّل. ملف SQLite مخصص لهذا الجهاز ومستخدميه المصرح لهم. يجهّز المشغّل الموثوق نطاق المؤسسة والمنشأة وفهرس الأدلة من المصدر المصرح له. تعكس حقول المراجع هوية المصدر وتاريخه فقط. الإسناد لا يثبت صحة محتوى المستند ولا يمنح صلاحية دخول إلى النظام. قبل أي نشر متعدد المستخدمين، يجب أن يربط المضيف الهوية الفعلية بالدور وبالمؤسسة والمنشأة، وأن يحضر الأدلة بنفسه.

## حصر الأدوار واختبارها

من جذر المستودع:

```sh
node automation/corporation/facility-routing.mjs list
node --test automation/corporation/*.test.mjs
```

## إعداد تكليف

أدخل كائن JSON باستخدام الإدخال القياسي. يعرض هذا المثال الاصطناعي نواقص الدليل لمهمة فحص الصيانة.

```sh
node automation/corporation/facility-routing.mjs prepare <<'JSON'
{"task":{"id":"sample.1","topic":"maintenance","intent":"prepare"},"host":{"tenant":"test-company","facility":"demo-building","asOf":"2026-11-28T08:00:00Z","evidence":[]}}
JSON
```

تحتوي كل خانة إثبات على `tenant` و`facility` و`type` و`reference` و`observedAt` و`expiresAt`. يقتصر المرجع على معرف مختصر. يقبل الموجّه التوقيت بصيغة UTC. تنتهي صلاحية الإثبات عند وقت الانتهاء نفسه.

تكون الحالة `awaiting_evidence` عند نقص المرجع، و`prepared` عند استيفاء مراجع الإعداد أو المشاهدة. يحيل الموجّه طلبات الدفع والتوقيع والصلاحيات والنشر والاستلام الفني والتدخل الحرج إلى صاحب صلاحية بشري. بعد اكتمال مراجع هذه الطلبات تظهر `awaiting_human_authorization`. تبقى المعاملة المالية أو الفنية في نظامها المخوّل.

## تنفيذ تحليل محلي بإيصال

لأوامر العمل مسار حسابي ينتج عدد الأوامر المفتوحة والمتأخرة والتي تفتقد موعدًا. وللميزانية مسار يجمع المعتمد والفعلي بالهللة ويحسِب الانحراف. يشتق الموجّه تكليف هذين المسارين من سجل المجلس. تبقى بقية الاختصاصات عند إعداد التكليف والمراجعة إلى أن يتوفر لها منتج مخرجات موثوق.

1. استخدم `operations.mjs DATABASE TENANT ingest SOURCE SNAPSHOT.json`. مفتاح المصدر هو معرف المنشأة، ثم نقطة، ثم `work_orders` أو `sar_budget`. ينشئ دفتر الأدلة نسخة ثابتة ويعيد رقمها. صيغة اللقطة في `knowledge.mjs`، والأمثلة التشغيلية في `operations.test.mjs`.
2. نفّذ `facility-routing.mjs observe DATABASE < scoped-input.json`. يحمل الإدخال حقلي `task` و`host` السابقين إضافة إلى `source` و`version`. استخدم `operations` أو `finance` للموضوع و`observe` للقصد. يجب أن يطابق مرجع الفهرس وتوقيتاه اللقطة المختارة. يعيد البرنامج نتيجة الحساب وإيصال الإسناد. يحفظ دفعة واحدة، ويعيد النتيجة عند تكرار الإدخال.
3. يزوّد المراجع المستقل المسؤول بنتيجة مرجعية منفصلة. يطابق `operations.mjs DATABASE TENANT review TASK CQO EXPECTED.json` كل حقل في النتيجة. يسجل الاختلاف ويتوقف. بعد نجاح المراجعة فقط يستعمل المشغل `close TASK` ثم `report TASK` مع نفس بادئة الأمر.
4. أمر `pause` يوقف بدء العمل ومتابعة التنفيذ داخل دفتر المؤسسة، ويظل التقرير مقروءًا للمشغل. يستعمل المسؤول `resume` بعد معالجة العائق.

أُعيد استخدام النواة الداخلية وسجل الأدوار واختبارات المسارين من مراجعة المستودع 108 عند الإصدار `71d19479e5630a2324329975ef739eed6a27bdef`. أضيفت اختصاصات المرافق وتوجيه إثبات المنشأة. يستثني مُعدّ حزمة الموقع مجلد `automation` من ملفات الاستضافة. تختبر الحالات بيانات مصطنعة في ذاكرة العملية أو مجلد مؤقت؛ لا يُرسل بريد أو إشعار ولا يُستدعى نموذج مدفوع عند تشغيلها.
